## 目标与不变量

一次普通聊天由 `ChatTurn` 固定 `TurnId`、用户消息 `MessageId`、输入和 `SessionSnapshot`。一个会话内的 Turn 按入队顺序串行执行。请求期间不再重新取当前用户和角色来构造 Prompt、搜索、聊天上下文或写入回复。会话版本变化后，旧网络请求中止，旧队列丢弃，旧结果不显示、不写回复、不增加关系值。当前用户输入在模型消息数组中只出现一次。

`SessionSnapshot` 是身份和展示字段的请求时副本；`GlobalSession.IsCurrent` 仍是结果提交前的有效性判定。用户/角色 ID 与版本用于身份判定，名字不用于判定。队列中的用户消息直到实际开始执行才落库，避免后续 Turn 被前一轮当成历史。用户确认：切换会话时移除尚未执行的用户气泡；聊天窗清空并加载新用户/角色最近 20 条记录。

| `ChatMessageService` / `RelationshipService` | 增加接收快照的落库和关系更新入口，避免主链重新读取当前身份。 |

这些是本轮开始时 `git status` 中已经存在的工作区改动，不应归为本轮新实现。原实现的主要未闭合处是：旧请求没有立即 Abort；网络错误仍通过字符串回调进入成功路径；主动气泡异步返回时窗口标题可能被后来的事件覆盖；搜索缓存没有会话维度。

## 本轮补齐

| 区域 | 改动 |
| --- | --- |
| 网络请求 | `AIChat` 跟踪活动 `UnityWebRequest`，设 30 秒超时，在会话版本变化、组件停用时 Abort，并在协程结束时 Dispose；主动气泡也可单独取消。 |
| 回复终态 | 普通聊天使用 `ChatReplyResult` 表示成功/失败。HTTP 或解析失败、空回复不会保存 Assistant 消息、增加回复成功关系值；UI 只显示未落库的重试提示。 |
| 异步边界 | 搜索决策、网页搜索后再次检查快照；会话失效不继续构造 Prompt 或启动下一阶段请求。会话变化同时取消队列和活动请求。 |
| 搜索上下文与缓存 | 搜索决策使用的最近文本也排除本轮已落库输入；缓存按用户 ID、角色 ID、会话版本隔离，换会话清空，仅非空成功搜索结果可加入。 |
| 主动气泡 | 触发时捕获快照、标题和进程名，限制一次在途气泡；结果在显示和事件落库前校验快照。网络失败不再记录成用户主动忽略。组件停用取消其气泡请求，切会话隐藏已显示气泡。 |
| 数据库写入 | `ChatMessageService` 在写入边界再次调用 `IsCurrent`；主动气泡事件使用触发时快照写入，失效结果不写事件或关系状态。同步查询、关系入口、管理 UI 和仓储中的直接 `GlobalSession.Current*` 读取也改为快照；删除当前用户的保护使用稳定 UserId。 |
| UI | 排队但未落库的气泡按 `TurnId` 追踪，取消时移除；会话变化后清空聊天窗并加载新身份最近 20 条消息。 |
| 身份约束 | `GlobalSession.SetSession` 验证角色归属，`SetCurrentCharacter` 不接受其他登录用户的角色；有效登录要求用户和角色 ID 均存在。 |
| 日志 | `AIChat` 销毁时解绑其全局日志订阅；聊天写库日志仅记录消息 ID，不再记录原文。 |

## 待处理风险与决策

1. **用户改名数据库关联**：`CharacterProfile` 仍以 `UserName` 归属用户；`UserRepository.UpdateUser` 只更新 `User`，改名可能使角色查找失败，快照无法修复。用户确认将此单列为后续数据库迁移阶段；届时先备份，再在脱敏数据库副本上设计和验证迁移。本阶段没有改 schema 或实际数据库。
2. **终态协议仍较薄**：普通聊天有成功/失败和会话取消路径，但没有独立的 `Cancelled`、`Timeout` 数据类型或可观测的请求状态记录；超时目前通过 `UnityWebRequest.timeout` 进入失败分支。若后续需要精确重试和诊断，应扩充终态类型和一次性完成约束。
3. **意外异常**：数据库异常、Prompt 构建异常或事件监听者抛错仍可能打断队列；现在处理了预期的网络/解析/空回复失败，但未建立所有异常的统一恢复与事务边界。
4. **资料更新和历史权限**：现有用户/角色重命名可能使会话展示名称与数据库快照不一致；`ChatHistoryPanel` 的搜索和删除范围没有随本次会话隔离改造。需要单独确认管理端是否允许跨用户历史查询与删除。
5. **日志与验证**：`AIChat` 的日志回调虽已解绑，仍同步写文件，其他日志可能包含窗口标题；未做脱敏、轮转。Unity Editor/Windows x64 Player、网络失败、气泡和数据库副本回归均待执行。
6. **既有角色编辑判断**：`CharacterRepository.UpdateCharacter` 对“新名称等于当前角色名”返回“默认角色不能删除”，与编辑语义不符；本轮只将其会话读取改为快照，没有改动这条业务规则，建议单独确认期望行为。

## 建议交给下一阶段 LLM 的验收场景

- 连续快速发送 A、B：数据库顺序为 A 用户消息、A 回复、B 用户消息、B 回复；A 的请求体没有 B，也没有重复的 A。
- A 正在搜索决策、搜索或 LLM 阶段时切角色/退出/重新登录：旧请求被中止；旧 Assistant、气泡事件和关系更新均不进入新会话；尚未执行的用户气泡消失。
- 新角色登录后聊天窗只显示该用户/角色最近 20 条历史；已保存但被取消回复的旧用户消息仍留在旧角色的历史。
- 前台窗口 X 的主动气泡请求未完成时出现 Y：回复、忽略事件、冷却键都归 X；切会话后 X 不显示也不写事件。
- HTTP 错误、超时、解析失败或空回复：保留已保存用户消息，不保存错误字符串为 Assistant，不增加成功关系值，队列能继续处理下一轮。
- 在**备份后的脱敏数据库副本**上检查用户名修改、历史查询和删除权限；不要对实际 `persistentDataPath/iroha_ai.db` 做实验。
