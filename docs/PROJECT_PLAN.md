# AI 桌宠 · 客户端工程化更新计划
## 2026-09-21 / 基于当前仓库的实施版本

目标：把已有桌宠、樱町场景、列车演出和视觉内容接成可演示、可解释、可验证的 Unity 客户端作品。

# 01 · 已经有什么，旧计划怎么改

桌宠基础已有：登录、用户/角色管理、非流式聊天、搜索判断/缓存、历史查询、关系与情绪、主动气泡、窗口布局与拖拽吸附。SampleScene 是唯一构建入口。

平台隔离大部已有：IWindowService、WindowsWindowService、Native DTO/ABI、x64 DLL、版本/能力自检。不应把整个 Native Plugin 重做一遍；前台感知仍直接 user32，需补齐边界和当前 Player 验证。

3D 内容已有：3DScene、樱町列车/栏杆/六灯循环、专用隧道裁剪、樱花 VFX、天空旋转、八份 A 版人物材质引用。Timeline 已绑定四个非空音频 Clip，场景 movementLoop 非空；有引用不等于听感验收通过。

当前列车：0 秒预警；3 秒红灯；5 秒落杆；10 秒出洞；20 秒停稳并开始抬杆；23 秒绿灯；25 秒抬杆完成；35 秒发车；45 秒隐藏；180 秒循环。停站仍为 15 秒。旧 30/45/65 时序不再作为现行规格。

尚缺产品连接：WorldService、进入/退出 UI、场景资源所有权、角色交互执行链、世界存档。YooAsset、UniTask、Cinemachine、HybridCLR 未安装，项目 Assets 下未发现 asmdef。

旧计划修订：
- P0 全仓搬到 _Project：改为先抽生命周期/接口，保留资源 GUID，逐模块迁移。
- P1 从零重做列车：改为复用现有循环，新增角色/镜头欢迎与退出处理。
- P1 15 秒列车 Intro：移除独立列车轨，避免和 20 秒停稳的现行循环冲突。
- P5 平台收尾：提前把阻塞边界与冒烟检查并入 M0，不再留到末尾。
- P4 性能：M1 就采基线，后期再形成优化前后证据。
- HybridCLR/多人：继续后置。房间世界等首世界闭环和资源交付稳定后再做。

# 02 · 架构审查：先解决会导致返工的问题

R01 平台边界：DesktopContextManager 的 3 处 user32 DllImport 仍在 Presentation。建议新增平台侧前台上下文服务，返回标题/进程数据；业务不接触 HWND。这是拟议接口，现有 IWindowService 不含该查询。

R02/R03 对话正确性：UI 先保存输入，ChatContextBuilder 又把当前输入追加一次；多请求和 GlobalSession 的即时读取会让旧回复归入新角色。建立 turnId、固定会话快照、取消和会话内顺序；只排除同 messageId，不按文本去重。

R04/R05 失败与取消：网络错误通过普通字符串回调，UI 仍保存并增长关系；请求缺统一超时、释放和取消终结，气泡锁只在回调里释放。引入结构化结果，一次请求只允许一个终态，失败和取消不能记为成功。

R06 生命周期：AIChat 每次 Awake 匿名订阅全局日志而不解绑，同步逐条写盘。世界重复进入会放大问题。应用级唯一日志服务负责轮转与脱敏，视图只订阅显示。

R07/R08 数据：角色按 UserName 归属，UpdateUser 仅修改用户记录；新增世界表会放大名称关联问题。先备份和稳定 ID 映射、事务及 schema 版本，再做 WorldVisit/WorldState。

R09 世界接入：直接替换场景会销毁 UI/协程；直接叠加会留下双相机、输入、音频或透明穿透。必须明确 App/Session/World/View 四种所有者，并提供失败回到桌面的补偿路径。

R10 演出所有权：循环独占列车/杆/灯；欢迎只管角色/镜头，动作队列在 Intro 期间锁住。Stop、Skip、Exit 都需要恢复控制权。

R11/R12 交付：搜索缓存需隔离会话与失败结果；原生 DLL 的源码版本/构建方式与导入平台配置需登记。仓库内未发现该 DLL 对应 C/C++ 源码，不能声称可独立重建。

详细证据入口及触发条件：docs/ARCHITECTURE.md。以上是静态审查，不把推导风险冒充已运行复现；本轮未修复这些代码。

# 03 · 增量架构与世界契约

建议采用“常驻桌面壳 + Additive 世界”，先用本地资源实现。桌面和站台共用账号/角色身份，世界视图不能成为数据库或平台服务的所有者。

所有权：
- AppScope：配置、日志、平台、数据库、资源入口。
- SessionScope：userId、characterId、sessionVersion、对话队列与取消。
- WorldScope：worldInstanceId、场景/资源句柄、角色实例、POI、动作、Timeline、音频/VFX。
- ViewScope：输入和显示订阅，销毁即解绑。

状态建议：Desktop → Entering → Intro → Explore → Exiting → Desktop；进入失败转回 Desktop 并展示错误。进入期间重复点击合并/拒绝；退出幂等，不能重复保存访问记录或释放句柄。

拟议接口：IWorldService.Enter/Exit、IResourceService.Load/Release、IConversationService.Send/Cancel。由窄 DTO/结果描述状态，World 不直接引用 YooAsset，UI 不直接管理资源句柄。函数签名在实施时结合项目异步选型确定。

进入顺序：冻结会话快照 → 保存窗口样式/布局/bounds → 暂停桌面交互/主动气泡 → 加载世界 → 校验绑定 → 生成/绑定角色 → 切换相机/输入/音频 → Intro/Explore。每一步记录已完成资源，失败逆序撤销。

退出顺序：拒绝新动作 → 使 worldInstanceId 失效并取消工作 → 停 Timeline/音频/VFX → 解绑事件 → 保存低频状态 → 销毁实例/卸载场景/释放句柄 → 恢复桌面窗口与输入。持久化失败提供错误与重试状态，不冒充保存成功，不让窗口永久卡在退出中。

渐进程序集拆分：先 Contracts/Platform，再独立服务，最后 World/Presentation。自定义 asmdef 不能反向依赖 Assembly-CSharp；每次抽取都检查完整依赖闭包。没有隔离收益时不为数量拆程序集。

这一页为实施建议，不代表这些类型已存在。无需以“所有接口全部抽完”为进入 M1 的前置条件。

# 04 · M0：把现有基础变成可靠入口

工作量建议 4-7 个有效开发日，先解决世界切换会放大的问题。

M0-01 建立现状回归：在当前版本构建 Windows x64，记录登录、聊天、历史、管理、布局、透明、拖拽、多屏/DPI、穿透与主动气泡。记录失败而非自动标完成。保存构建版本与环境。

M0-02 对话用例服务：UI 只发送输入和显示结果；请求捕获身份和 turnId，会话内先采用串行队列。换角色/退出登录时取消旧请求，过期回调不落库；同一输入在 messages 中只出现一次。

M0-03 统一终态：Success/Failure/Cancelled；超时、HTTP 错误、无效 JSON、空回复、主动取消都能释放锁/请求。错误单独展示，不能增长关系或保存成正常助手回复。为这些边界编写有实际价值的故障测试。

M0-04 日志和配置：应用级唯一日志订阅、退出解绑；端点/模型/超时进入配置；密钥留本地，缺失配置给可定位提示。默认 Prompt 缺失时停止初始化并显示错误。

M0-05 平台接缝：迁出前台感知 Win32；保留现有 IWindowService。检查原生导入平台、自检失败降级和 x64 Player 行为。增加接口应基于可访问的原生源码，否则先用平台侧托管适配并记录限制。

M0-06 数据基线：备份脱敏库，建立 schema 版本；制定并实现用户名关联到稳定 ID 的兼容迁移，验证重命名、删除、当前角色约束和事务失败。世界表暂不提前全建。

M0 完成条件：
- 两轮快速发送、请求中换角色、断网、超时、解析失败后仍可继续聊天。
- 请求不重复入上下文，不跨会话写入，失败不加关系。
- 重建视图后日志仅记录一次，退出无残留订阅。
- 数据迁移可在旧库副本重复验证，失败不产生半修改。
- 原有桌宠路径没有已知回归；平台未通过项明确阻塞 M1 发布验收。

# 05 · M1：桌宠与站台往返的最小闭环

工作量建议 5-8 日。第一版先做到“可进、可看、可退、可恢复”，不依赖远端下载。

M1-01 薄应用协调器：新增 Entering/Explore/Exiting 状态和 WorldScope，不让场景脚本互相 Find。只允许一个世界实例；进入按钮防重入，退出可在加载途中请求。

M1-02 本地资源适配：IResourceService 首版包装本地场景加载和资源引用。明确句柄由 WorldScope 持有；本地加载不假装正在下载，不显示无依据的完成百分比。

M1-03 世界目录：配置 WorldDefinition，首项映射现有 3DScene。为本地 Player 将所需场景纳入构建；验证资源引用不依赖编辑器 AssetDatabase。

M1-04 输入/窗口切换：保存桌面窗口快照，站台模式关闭穿透并切换合适尺寸；暂停桌面主动气泡和闲置相机，保持一个 AudioListener 和有效输入系统；回桌面恢复原样。

M1-05 复用视觉：绑定现有循环、A 材质、樱花与音频。先检查 0/3/5/10/20/23/25/35/45/180 秒的画面和跳转恢复；不运行会覆盖手工音轨的配置操作而不先检查其行为。

M1-06 正常/异常退出：加载失败、用户取消、场景缺失、绑定错误、退出中再次退出均回到可交互桌面。Unity 加载不能直接取消的阶段，允许完成加载后立即清理，不能留下隐藏场景。

M1-07 基线采样：记录机器、分辨率、质量、图形 API、版本；连续进入退出 20 次，观察场景、实例、事件订阅、活跃音源和内存趋势。

M1 完成条件：Windows Player 可完整“登录 → 进入站台 → 看至少一轮循环 → 返回桌面 → 继续聊天”；加载取消/失败后桌面恢复；20 次往返无持续增长的受管对象/句柄/订阅，内存缓存需解释，不能要求进程内存机械归零。

交付证据：往返演示、失败演示、生命周期图、加载耗时与内存基线。此阶段不把离线聊天模型设为硬前提，外部 API 失败仍可返回桌面。

# 06 · M2：站台交互、角色与欢迎演出

工作量建议 5-8 日，在 M1 生命周期上增量增加。

角色前置检查：核验当前模型 Avatar/Humanoid、骨骼、Animator、动画许可与 Root Motion。未核验前不能承诺现成模型能直接用任意动作包。先有 Idle/Walk/Wave/Nod 最小集。

角色门面：CharacterFacade 统一移动、看向、Emote。建议 NavMeshAgent 负责位移，Animator 负责外观，禁止两者同时写根位移。不可达、超时、目标卸载都返回显式结果。

内容最小集：先一个贩卖机 POI，再扩展茶摊和观景点。每个 POI 配置稳定 ID、站位、看向、允许动作和冷却；“取饮料”先用 UI 选择/通用动作，不依赖精准抓取或复杂坐下。

手动交互先行：点击 POI → 校验 → 排队 → 到达 → 看向 → 动作/对话 → 结果。ActionQueue 先服务按钮，再复用于 LLM。首轮只支持 Speak、MoveToPOI、LookAt、PlayEmote、Wait。

欢迎演出建议：进入世界循环从 0 开始；镜头展示现有入站过程，在 20 秒停稳阶段播放回头/挥手/欢迎，随后进入 Explore。镜头和角色有独立控制权，列车继续现行时序。可跳过欢迎立即 Explore，不能让跳过操作改变列车时间。

Cinemachine 只在镜头需求出现时引入，先在 2021.3 上验证官方 2.8 系列，再锁具体包版本。不要默认安装 3.x。Timeline 控演出，Animator 控持续状态，相机系统控镜头；为 Stop、Skip、Exit 释放交互锁。

M2 验收：每个 POI 正常、不可达、动作超时、执行中退出、快速重复点击都结束明确；欢迎跳过/停止不残留控制锁；两轮列车仍保持 180 秒，音频没有重播叠加；没有第二个系统写列车。

世界只保存访问和有意义的交互结果。房间世界先不做，等首世界和资源交付证明同一接口可复用。

# 07 · M3：资源热更新与可回退交付

工作量建议 7-10 日。延续 YooAsset 3.x 方向，但先做目标版本兼容实验再锁定 tag；当前仓库未安装，不把旧计划版本结论当作集成结果。

兼容实验必须覆盖：Unity 2021.3.21f1c1、中国版编辑器环境、当前构建后端、URP 材质/Shader、VFX Graph、Timeline、音频、SQLite/Native 插件随客户端分发。只有通过实际 Player 加载才进入主线。

资源边界：客户端随包保留登录/桌面/Loading/平台/数据库；初版优先一个世界内容包，用标签或分组区分站台、人物、共用音频/VFX、活动。旧计划的五个 Package 不必同时创建，先检查共享依赖重复和更新频率再拆。

ResourceService 包装 YooAsset，全项目只有适配模块接触具体 API。每个实例/场景持有可追踪句柄，退出释放；不要用强制 GC 代替句柄和对象所有权。

更新流程契约：初始化 → 查询版本 → 清单校验/兼容检查 → 计算大小 → 确认下载 → 下载/验证 → Ready → 加载。取消、断网、404、磁盘不足、文件损坏提供错误/重试；有完整旧版本才允许离线回退。

发布契约：构建不可变版本目录 → 上传 bundle/manifest → 完整性验证 → 最后切换版本指针。记录客户端最低版本、资源版本、环境、Git 版本、构建时间和校验信息。回滚指向上个兼容版本，并保持其文件可获取。

服务器：使用用户届时确认的静态资源源站，区分 dev/test/prod；不假定旧文档中提到的云机目前仍存在或可用。公网分发采用 HTTPS。静态资源服务器与多人同步后端是两件事。

M3 验收：新装、缓存命中、差异更新、下载中断重试、错误清单、旧客户端拒绝不兼容资源、回滚、离线旧版本均演示。更新一处装饰/音效后不重装客户端可见，退出世界后句柄释放。保留构建报告、发布日志、故障与恢复录像。

# 08 · M4：受限 AI 动作与世界记忆

工作量建议 4-7 日。M2 的手动动作链稳定后接入；可以在 M3 前做最小原型，但不要同时推进两个高风险集成。

协议建议：ActionRequest 包含 requestId、sessionVersion、worldInstanceId、actionId、参数和超时；ActionResult 包含 Success/Failure/Cancelled、原因和实际执行摘要。版本化 schema，限制文本长度、等待时间和队列长度。

模型只能输出白名单 ActionId 和合法参数。ActionValidator 核验 schema、当前世界/阶段、POI、冷却、权限和参数范围。未知动作、对象路径、任意脚本、过期世界实例全部拒绝；Speak 文本不自动变成第二条可执行命令。

执行链：用户/世界上下文 → 模型规划 → 校验 → 串行动作队列 → CharacterFacade/对话执行器 → ActionResult → 数据与上下文。先实现五种基础动作，组合贩卖机行为由受控配置形成，不任由模型创建无限动作序列。

退出世界/换角色/高优先级演出取消相关动作；取消必须终止实际移动/动画控制，并反馈结果。只有真实成功才记成功历史，模型不能自行断言动作完成。超时与失败不让队列永久阻塞。

数据增量（拟议，尚无表）：WorldVisit 记录 visitId/userId/characterId/worldId/进入退出时间/版本；WorldState 用稳定 ID 复合键保存低频状态；ActionHistory 记录 requestId、actionId、结果和耗时；ResourceState 记录最后成功版本与状态。统一使用 CharacterId，避免旧计划 RoleId 与账号权限 Role 混淆。

每批 schema 变更有版本、事务、备份和旧库升级验证。访问/动作摘要可进入 Prompt，Transform 高频状态不写 SQLite。桌面回来引用“上次访问/选择”不等于实现向量数据库或长期记忆系统。

M4 验收：合法动作、非法参数、未知 POI、模型乱格式、超时、取消、会话切换、重复 requestId 都有确定结果；模型失败时手动交互仍工作。演示动作失败被如实告知，而非仅录制顺利路径。

# 09 · M5：性能、内容工具与扩展边界

接下来两周只推进 M0 + M1：
1. 前 1-2 日建立当前 Player 基线和风险复现。
2. 随后完成请求/会话/日志/平台接缝及数据迁移最小控制。
